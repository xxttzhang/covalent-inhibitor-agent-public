# Ligand-first 默认直接 LO

用户确定的目标（2026-11-11）：小批量候选独立准备后直接 LO，大批量先 VS 再 LO；在固定版本的新网页会话验收到姿态报告，不执行 MD。

## 路由合同

唯一策略定义：`science/src/covscreen/ligand_docking_policy.py`。

- 对经化学身份核验及立体化学审阅的完整批次计数，1–6 默认 `direct_lo`，7 个以上默认 `vs_then_lo`。
- 数量为零时不产生计算路径。不以先截断候选列表的方式规避大批量策略。
- 少量候选可显式选择 VS 并记录理由。当前策略不自动扩大直接 LO 预算。
- 路由回执记录策略版本、数量、请求路径、选择路径及理由；它不授予计算权限，也不代表科学通过。
- 历史冻结任务按原始来源核验，原判断不修改；用户明确变更评估策略时，可用已有产物生成独立的新评估记录，并保留旧判断。

## 执行链与验证边界

候选生成 → 化学身份与立体化学核验 → 独立受体／配体准备 → 原生审批 → asgbie3 LO → 原始产物核验 → 姿态评估与报告。

直接 LO 需要新的来源类型，不借用 `registered-ligand-vs-review-v1`。候选原始分子、母体参考、受体来源、准备产物及计算输入均绑定哈希。不得凭空生成 source_run_id 或上游几何 PASS。

VS→LO 路径保留，但需要区分预筛用途与最终 LO 几何判据。禁止直接把 VS 姿态交给 MD。接触定义与门禁问题独立记录；本轮不通过降低门禁保证候选通过。
