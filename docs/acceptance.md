# 网页用户验收合同

目标是用户能通过网页完成受支持的研究流程，所有开发者介入均记录为缺陷。
源码和构建验证先完成；运行时不与原服务共用可写研究目录。
不得把旧会话的完成记录当作新工程已经执行成功。

## 范围

- Ligand 与 Library：登记范围内的靶点/位点/方案，从新研究开始到候选评价、
  MD 图准入、参数化、体系准备、短程 QC 与平衡。
- 科学门槛不满足时正确停止、保留证据并解释原因，也属于合法交付分支。
  但某案例提前终止不能证明未经过的后续阶段已验收；需单独覆盖它们。
- 生产 MD、轨迹分析与最终 MD 报告列为后续统一编排工作。
- De novo 保留代码和验证版本，完整流程不作为本次验收完成证据。

## 必须留下的证据

1. 本次源码清单、前后端构建身份、科研发布、运行环境和配置摘要。
2. 每条路线的新会话/研究 ID、用户输入、实际使用的网页地址和阶段记录。
3. 必要的批准参数、任务身份、真实执行/排队/失败状态和输出核验。
4. 网页上的结果、来源、阻塞原因与重新打开会话后的状态。
5. 失败、取消/超时、断连和恢复覆盖；确认没有重复提交、串研究或继承旧批准。
6. 每次人工补路径、改后台文件、重启、修代码或搬运数据的复现步骤和复验结果。

计算只在明确计划与所需原生批准下进行；测试目标不等于无限算力授权。
最终报告逐项标注通过、失败、未测、外部条件未满足，不能用单元测试代替网页执行。
