# Inspire CLI workspace compatibility

Acceptance found that CLI 7.1.14 expects `userWorkspaceList` in `user.GetRoutes`, but the current control console uses `user.ListAccessibleWorkspaces` and maps `items[].workspace_id/name/is_fair_workspace` into its workspace selector. The old lookup prevents scheduler dry-run for both routes.

`workspaces.py` is the installed 7.1.14 module with this bounded contract update. It uses the existing authenticated Browser API transport and envelope parser. Missing or non-boolean policy, invalid identities, duplicate IDs and malformed responses fail closed. It does not invent policies, change permissions, authenticate another account or submit workloads. The existing scheduler selection, quota checks and native approval remain intact.

`install.py` requires the exact original module hash, saves a private backup and atomically replaces only that module. It is a local CLI installation change, affecting subsequent invocations of that installed CLI; it is not limited to one chat. Do not apply to another CLI version or automatically overwrite an upstream update. Review a changed version first. Restore the verified backup only when intentionally rolling back this compatibility update.

Run `test_workspaces.py` with the installed Inspire Python interpreter. The five parser tests cover explicit true/false, malformed envelopes, unknown policies, duplicate/invalid identity and explicitly empty lists. Also run the original registered plan with `--dry-run` before resuming it through the web. Passing preflight is not scheduler submission or scientific acceptance.

Evidence is external to source: `console-contract-discovery.log`, `qz-index.DRzQPNV7.js`, `current-workspace-policy-diagnostic.log`, `compat-library-preflight.log`, and `installed-compat-library-preflight.log` in the acceptance evidence directory. The actual installed module hash is part of the runtime identity, separate from the already-running host and frozen scientific releases. `install.py --bootstrap` also updates the three existing workspace-discovery call sites in session initialization through their shared URL/body/parser. Its AST regression proves unrelated authentication code is unchanged; this does not claim a fresh-account login was tested. The workspace endpoint has no selector, so it works before a workspace has been selected. The formal CLI workspace cache refresh was verified after this repair; no cache entries were hand-written.
