## 固定阶段与责任

`prepare → parameters → short_qc → production → trajectory_audit → analysis → report`

每个候选、独立重复使用独立不可变计划。计划固定体系身份、源文件哈希、化学状态、精确 OPLS 版本、模拟时长、帧间隔、脚本和解释器身份，以及每阶段时间上限。内核只调用主机登记的适配器，不接受模型任意命令；只能在已授权的计算资源中运行，本身不批准或提交资源。

子适配器使用 `--plan --stage --output --upstream` 接口，输出 `evidence.json` 及其文件清单。证据绑定计划哈希、run_id、化学状态和阶段。参数、结构与轨迹检查必须由实际科学程序完成，不能仅填入 PASS。文件哈希提供完整性，不证明科学正确性。

内核逐阶段验证证据，每次推进重新核验上游文件；进程退出码 0、Job SUCCEEDED 或存在 DCD 都不足以完成任务。并发进程使用锁，已验收阶段不会重跑；失败或中断保留现场并停止。**当前不实现自动断点续跑**：后续须先审计 checkpoint、帧时间重叠/缺口、同一参数身份以及剩余预算，再登记受控恢复适配器，禁止无限重试或覆盖旧轨迹。

## 两种化学状态不能混用

- `pre_covalent`：检查反应物结构图、亲核残基状态及局部准备合理性。NAC/gating 仅作观测，反应几何离开不能单独使准备失败；禁止永久反应距离约束。分析需要冻结反应原子映射与几何定义。
- `covalent_adduct`：检查实际共价连接参数，分析构象、相互作用、蛋白/口袋变化及共价几何；不得输出 NAC/gating 作为反应前采样结论。
- 两种状态都不能凭 MD 稳定性声称已证明亲和力或 kinact。自动报告完成与专家审阅完成分开。

## 后续接入顺序与验收

1. Library-first 科学适配器：源姿势与序列追溯 → Schrödinger 补环 → 连接/手性/电荷 QC → OPLS 指定 → OpenMM 转换核验。核对许可证与原生工具，不用注入或绕过许可。
2. 通用运行器：以冻结计划替代候选名、残基数和 10 ns 常量；短程无约束检查通过才进入生产段。
3. 原生 MD 工具及持久观察器：同一用户消息去重；原生批准绑定体系、费用/时限和输出范围；通过 InspireSkill 的 Job/HPC 提交；提交响应不确定时只对账，不重复创建。
4. 通用分析器：完整轨迹读回、PBC 与对齐检查，蛋白/配体 RMSD、COM、口袋接触、氢键、温度/密度等；按化学状态选择 gating 或加合物几何。保留重复间差异，不将相关帧当独立重复。
5. 原生 Results 回写：逐文件校验、表格/图像/报告及来源清单。自动生成只标记待科学审阅；明确采样不足与缺失指标。
6. 在平台发起一个真实端到端验收任务，验证页面关闭/进程重启后恢复观察，再扩展到 8 个候选。小型软件子进程测试不算真实 GPU 验收，也不自动授予扩量权限。

验收标准：用户在平台选择候选并确认一个有上限的运行方案，平台自行准备、执行、审计、分析与交付；不需要 Codex 手动逐阶段提交。科学失败、资源失败、分析失败和交付失败分别保留。
